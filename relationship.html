How LangChain and LangGraph fit together

They get mentioned in the same breath so often that it's easy to assume they're the same thing, or two versions of the same thing. They're not. This page explains the difference — and every section ends with a simple hint for the idea, the way you'd explain it to a 10-year-old.

🧒 Start here

LangChain is a box of tools. LangGraph is the person deciding which tool to pick up next — and what to do if something doesn't work the first time.

1. What LangChain actually is

LangChain is a collection of separate, ready-made pieces for working with an LLM. Each piece does exactly one job — loading a file, splitting text, turning text into numbers, storing and searching those numbers, formatting a prompt, calling the model — and none of them know or care what happens before or after them. They're independent tools, not a plan.

🧒 Like you're 10

Think of a pencil case: a pencil, an eraser, a ruler, scissors. Each thing is useful on its own. But the pencil case itself doesn't tell you what order to use them in for your homework — that's not its job.

2. What LangGraph actually is

LangGraph doesn't do any of that work itself. It's the flowchart that says "do this step, then this step — and if this happens, go back and try a different way." It keeps track of what's been learned so far as it moves between steps ("nodes"), and it can branch, loop, or retry — things a single tool, or a single prompt, can't do on its own.

🧒 Like you're 10

Now imagine your homework instructions: "Read the question. Look it up. If you're still not sure, look it up again a different way. Then write your answer." That plan — including the "if you're not sure, try again" part — is what LangGraph is. It's the plan, not the pencil case.

3. How they relate — LangGraph is the plan, LangChain fills in some of the steps

This is the part people mix up: LangGraph doesn't replace LangChain, and LangChain can't do what LangGraph does. LangGraph is the outer shape — the order of steps, and what happens when a step succeeds or fails. Some of those steps happen to use a LangChain tool. Some don't need to at all. 🧒 Like you're 10

LangGraph is the plan: "Step 1, Step 2, Step 3." For Step 1 and Step 3, the plan says "grab a tool from the pencil case" (that's LangChain). For Step 2, the plan just says "use your own two hands" — no tool needed. LangGraph doesn't mind either way. It only cares about what order things happen in, and what to do if a step doesn't work.

4. Side by side

LangChainLangGraph
What it is A toolbox of ready-made pieces (load, split, embed, search, prompt, call model) A flowchart/state machine that wires steps together in a chosen order
Good at Doing one well-defined job really well Deciding order, branching, looping, retrying, remembering what happened so far
Not built for Deciding what order to do things in, or what to do if a step fails Loading files or calling an embedding model itself — it delegates that to whatever a step uses
🧒 Kid version The pencil case The homework plan
Bottom line: LangGraph is not "LangChain, but newer" — it's a different layer that sits around LangChain (and around plain code, when that's all a step needs). LangChain supplies ingredients; LangGraph supplies the recipe.

5. So which one do I need?

Need one well-defined job done (load a file, search for similar text)? That's LangChain. Need several steps done in order, with branching or retries? That's LangGraph. Need both, wired together? That's this whole repo — see formula_when_to_use.md for the full use-case breakdown, and the How it's wired section back on the main page for how these two pieces plug into the actual PoC.

🧒 One more time

If you only need one tool, just grab the tool — you don't need a whole plan for using one pencil. But the moment your homework has more than one step, and some steps depend on how the last one went, you need a plan. That plan is LangGraph.
